## 2. The executables: four build targets per region

The game uses a chained multi-executable layout. A small boot executable launches three larger payloads from disc. Each executable is a separate byte-exact target with its own hash file under `config/sha1/`.

| Target | Disc file | Size (B) | Payload (B) |
| --- | --- | --- | --- |
| `slps_00270` | SLPS_002.70;1 | 290,816 | 288,768 |
| `sces_00269` | SCES_002.69;1 | 290,816 | 288,768 |
| `mainmenu_jp` | MAINMENU.EXE;1 | 698,368 | 696,320 |
| `mainmenu_eu` | MAINMENU.EXE;1 | 700,416 | 698,368 |
| `g3_jp` | DRAGOON/G3.EXE;1 | 575,488 | 573,440 |
| `g3_eu` | DRAGOON/G3.EXE;1 | 577,536 | 575,488 |
| `g3org_jp` | GOURB/G3ORG.EXE;1 | 628,736 | 626,688 |
| `g3org_eu` | GOURB/G3ORG.EXE;1 | 630,784 | 624,768 |

Payload size equals file size minus the 0x800-byte PS-X EXE header. The primary release is Japan. The European release is the secondary target.

**The target hashes are NOT repeated here.** The only authoritative hashes are the committed oracles `config/sha1/<t>.sha1` — post-flip (de0b0d68) they carry the PER-SECTOR TRUE extractions' hashes, and the witness gate (sha1 of a local `baselines/<t>.bin` vs that file; judge_unit's baseline_gate, verify.sh gate 2) is the arbiter of every baseline question. This table's earlier SHA-1 column encoded the PRE-FLIP contiguous-read (woven) extraction and was retired at cron-20261022-1043: a local baseline set matching those retired values is exactly the all-woven sandbox trap the honest witness checks keep catching (witness 0/8, never compare against it, never edit the sha1 file to pass). The disc-image hashes in section 1 are retail provenance and stay.

## 3. Header facts (all eight executables): corrected v2

Measurements generated by `tools/exe_map.py` (documented in `docs/LOADMAP.md`):

| Target | Entry `pc0` | Entry offset | Load `t_addr` | `t_size` | Init `$sp` |
| --- | --- | --- | --- | --- | --- |
| slps_00270 | `0x8002DB14` | `0xDB14` | `0x80020000` | `0x46800` | `0x801FFFF0` |
| sces_00269 | `0x8002D908` | `0xD908` | `0x80020000` | `0x46800` | `0x801FFFF0` |
| mainmenu_jp | `0x8005C530` | `0x3C530` | `0x80020000` | `0xAA000` | `0x801FFFF0` |
| mainmenu_eu | `0x8005C160` | `0x3C160` | `0x80020000` | `0xAA800` | `0x801FFFF0` |
| g3_jp | `0x80047EF0` | `0x27EF0` | `0x80020000` | `0x8C000` | `0x801FFFF0` |
| g3_eu | `0x80047B58` | `0x27B58` | `0x80020000` | `0x8C800` | `0x801FFFF0` |
| g3org_jp | `0x8004538C` | `0x2538C` | `0x80020000` | `0x99000` | `0x801FFFF0` |
| g3org_eu | `0x80044FAC` | `0x24FAC` | `0x80020000` | `0x99800` | `0x801FFFF0` |

All targets are standard PS-X EXEs. Each file is a contiguous payload that the BIOS loads at `0x80020000`. The entry `pc0` points within the image. `t_size` matches the payload size. Fields `data_addr`, `data_size`, `bss_addr`, `bss_size`, and `gp0` are 0. The program uses gp-relative addressing. The crt0 stub initializes `$gp`. The ASCII region marker at 0x4C reads `Sony Computer Entertainment Inc. for Japan area` or `... for Europe area`.

`SYSTEM.CNF` values on both discs: `TCB = 4`, `EVENT = 16`, `STACK = 801fff00`.

Game loader code controls the execution chain (boot → MAINMENU → DRAGOON/G3 or GOURB/G3ORG).

## 4. Disc contents (Japan release summary)

* Root: `SLPS_002.70;1`, `MAINMENU.EXE;1`, `LOGO.STR`, `MISSION.STR`, `MIN3.DA` (XA audio), `MTIM?.DAT`, `SE.VB`/`SE.VH` (sound bank), `TIM.DAT`, `TMD.DAT`
* `DRAGOON/`: `G3.EXE`, `TIM.DAT`, `TMD.DAT`, briefing/ending video (`*.STR`), character files (`*.DAT`: FRANK, JOHNSON, REIKO, SHARK), demo scripts
* `GOURB/`: `G3ORG.EXE`, `G3ORG.STR` (153 MB), `TIM?ORG.DAT`, `TMD1ORG.DAT`
* European media includes localized assets (`BRIEFE.STR` instead of `BRIEFN.STR`)

## 5. Toolchain fingerprint (Phase 1 findings)

Inside `SLPS_002.70`:

```
$Id: intr.c,v 1.71 1995/08/29 11:01:44 suzu Exp $
$Id: sys.c,v 1.109 1995/10/26 13:06:43 suzu Exp $
```

Sony Psy-Q kernel RCS tags date the linked SDK to **October 1995** (Psy-Q 3.x series). The working compiler hypothesis is **GCC 2.6.3**, which matches Psy-Q releases of that period.

Linked Psy-Q libraries: libapi, libetc, libcd, libcard, libgpu, libgs, libgte, libspu, libsnd, libpress, libc2.
