# Toolchain

This document details the toolchain used to reproduce project binaries. Components under **Proven** are required for `make verify`.

## Proven: the oracle is green with this exact stack

| Component | Version / source | Role |
| --- | --- | --- |
| splat | 0.50 (PyPI `splat64`) | Splits retail executables |
| spimdisasm | 1.42.4 | Disassembles binary sections during extraction |
| maspsx | Pinned clone (`tools-src/maspsx`) | Translates Sony ASPSX assembly for GNU as |
| GNU as / ld / objcopy | 2.31.1 (Debian buster `binutils-mipsel-linux-gnu 2.31.1-16`, amd64 host) | Assembler, linker, and objcopy |
| Python | 3.12 venv (`pyyaml`, `capstone`) | Pipeline tooling and mapping |

Set up the environment without root privileges:

```sh
tools/get_binutils.sh                      # downloads and extracts into tools-local/mipsel-root
python3 -m pip install splat64==0.50 spimdisasm==1.42.4 capstone pyyaml n64img pygfxd crunch64 intervaltree
make verify TARGET=slps_00270              # confirms: OK: build matches retail
```

Assembly flags (`tools/build.sh`): `-march=mips64 -mabi=32 -EL`.
The `mips64` target architecture prevents GNU `as` from expanding 64-bit pseudo-instructions (`ld`, `sd`) under o32. `build.sh` rewrites these instruction words to explicit `.word` directives based on disassembly comments. Subsegment linker scripts are generated by `tools/gen_ld.py`. The PS-X EXE header is generated by `tools/mkpsxexe.py` using `config/exe.json`.

## Working hypothesis (until pinned per-function)

Baseline build configuration: **GCC 2.6.3 + Psy-Q October 1995**.
Initial flags for C compilation: `-mips1 -O2 -G8 -funsigned-char -fno-builtin`. Inline break traps and delay slot scheduling match GCC 2.6.x MIPS output.

## Pinned: GCC 2.6.3, Sony PlayStation build (2026-10-10)

Target compiler: **GCC 2.6.3 [AL 1.1, MM 40] Sony Playstation**.
Acquired with `tools/get_gcc.sh` from `decompals/old-gcc` release 0.12 (`gcc-2.6.3-psx.tar.gz`). Because the 32-bit i386 binaries fail under restrictive seccomp filters, cc1 runs under `qemu-i386` (static, from Debian bullseye). Tools reside in git-ignored `tools-local/`.

Build pipeline (`tools/cc.sh`):

```sh
tools/cc.sh -o out.o file.c        # compiles .c to .o
tools/cc.sh -S -o out.o file.c     # stops at maspsx assembly (used by build.sh)
```

Processing order: cpp → cc1 → maspsx `--expand-div` → mipsel as 2.31.1.
Psy-Q cc1 requires source pre-filtered by cpp. The `--expand-div` flag replicates ASPSX macro expansions, emitting the `break 7` and `break 6` trap sequences seen in retail binaries.

Flags: `-mips1 -O2 -G8 -funsigned-char -fno-builtin`.

Probe evidence (`probes/gcc263/idioms.c`):

| Probe | Retail pattern | Result |
| --- | --- | --- |
| `a / b` (signed) | `func_80028B8C.s` trap chain | Exact match: `div $zero` + `bnez/nop/break 7` + `addiu $at,-1/bne/lui 0x8000/bne/nop/break 6` + `mflo` |
| `a / b` (unsigned) | divu row | Exact match: `divu` + `bnez/nop/break 7` + `mflo` |
| `a * b` | mult row | Exact match: `mult` + `mflo` |
| `p[i]` plain char | char signedness row | `lbu` (unsigned char) |
| `p[i]` signed char | minority row | `lb` (signed char) |

Confirmed cc1 defaults: `-mgas -msoft-float`, `-G 8`, `Cpu = 3000, ISA = 1`.

Linker behavior: GNU `as` pads default `.text` sections to 16 bytes on MIPS. Assembly subsegments do not carry this padding. C objects use an in-source section rename (`tools/build.sh` compiles via `cc.sh -S`, updates `.text` in the `.mas.s`, and calls `$ASFLAGS`).

First verified C match: `src/func_80036CFC.c` (stub with body `jr $ra; nop`), passing `make verify TARGET=slps_00270` on 2026-10-10.

## Hand-written asm in the source tree (classified 2026-10-10)

Certain retail routines are hand-written assembly rather than compiler output:

* Leading-nop store routines (`func_80025AE0`, `func_8002A0DC`: `nop; sw/sh $zero,off($gp); jr $ra; nop`)
* Adjacent `ori`-store pairs with delay-slot overlaps into the subsequent function
* GTE `ctc2` stub (`func_80037AC8`)

Compiling across optimization levels (`-O0` to `-O3`, `-G0/4/8`) across available flags produced no leading-nop functions. The cc1/maspsx toolchain fills delay slots consistently. These routines represent hand-written assembly in the original game and remain matched via volatile assembly wrappers or assembly stubs rather than pure C functions.
