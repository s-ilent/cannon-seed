## Queued

### Apply the carve-type pins — `docs/carve-pin.patch`

`tools/code_data_screen.py` flags 37 `asm` subsegments whose bytes are really
data (ASCII runs, zero runs, self-referential pointer runs, low plausible-opcode
fraction). The patch re-types them to `data` in the eight `config/splat.*.yaml`
maps and adds the `pinned` marker those lines need.

The marker matters: the subsegment block is regenerated by `make scan`, and
`preserved_types()` in `tools/scan_functions.py` preserves only `c` entries by
design — v3 rescues real code out of data gaps, so blanket-preserving `data`
would undo that. The patch teaches it to also preserve `data` lines marked
`pinned`, which makes them hard walk-stops. Without that hook, editing the yaml
alone is silently reverted by the next scan.

Per target:

    git apply docs/carve-pin.patch
    make scan TARGET=<t> && make extract TARGET=<t> && make verify TARGET=<t>
    tools/clean_stale_asm.py        # then check `git diff`

Scope: only the 37 DATA-verdict ranges are pinned. The 25 SUSPECT ranges are
left alone on purpose — they need a human call, not a rule.

Confirm afterwards: `python3 tools/code_data_screen.py --all` should no longer
flag the pinned ranges once re-scanned. If any reappear as an unflagged `asm`
without the `pinned` mark, the pin did not survive and the hook needs a look.

## Log

**2026-10-12 — static carve auditing.**
- `tools/code_data_screen.py` — flags code subsegments whose bytes are data. 37
  across the eight targets; calibrated against the known `0x80021800` =
  `CD_cachefile`.
- `tools/crossbuild_align.py` — aligns a JP/EU pair by unique-k-mer anchors plus
  LIS. Inside aligned regions the two sides are 88–93% byte-identical, against
  16–24% at fixed offset. Reports that ~35–44% of mappable boundaries disagree
  on code-vs-data.
- `tools/struct_infer.py` — clusters memory accesses into field maps with
  signedness (`lb`/`lbu`, `lh`/`lhu`); drops runs of identical non-nop words,
  which are data misdecoded as code.
- `tools/crossbuild_diff.py` — kept as a weak reference; its docstring records
  why fixed-offset byte-identity cannot validate boundaries here.
- `docs/TOOLCHAIN.md` — compiler-fingerprint table re-measured; the counts had
  drifted after the stale-asm cleanup.
- `docs/RUNTIME.md` — the PCSX-Redux runtime harness, plus its measured limits:
  exact-address Exec breakpoints fire, range breakpoints and watchpoints do not,
  the exe entry is not caught, and the GDB stub shares the same breakpoint
  store. It is not a carve oracle.
